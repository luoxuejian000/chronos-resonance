# GitNarrative —— 项目演化自传生成器

让 Git 仓库拥有“自我叙事”能力。基于**晶脉哲学 SNI（自我叙事整合器）架构**与**谐振动力学**，将 commit 历史转化为可读的项目演化自传。

## 为什么需要这个工具？

`git log` 是事件的堆砌。`git blame` 告诉你谁改了哪一行，但不告诉你“这次修改在整个项目的演化史中意味着什么”。

GitNarrative 回答三个问题：

- 项目**什么时候**是平稳发展期？什么时候是剧烈重构期？什么时候是混乱期？
- 项目的**整体健康度**如何？演化趋势是向好还是向坏？
- 如果项目是一本书，它的**章节**该怎么划分？

## 核心理论

GitNarrative 是晶脉哲学四重公理在 Git 历史分析领域的直接应用：

| 公理 | 分析维度 | 指标 |
|------|---------|------|
| 关系本体论 | commit 修改的聚焦度与文件耦合程度 | U（统一性） |
| 矛盾动力论 | 修复、回滚、冲突的强度 | A（对抗性） |
| 谐振调谐论 | 整体代码演化健康度 | H（和谐度） |

**和谐度函数**：`H = λᵤ·U - λᴅ·D - λₐ·A`

## 五种演化阶段

| 阶段 | 特征 | 和谐度指标 |
|------|------|-----------|
| 📐 平稳发展期 | 修改聚焦，代码库结构稳定 | 高U 低A |
| 🔧 剧烈重构期 | 大规模代码替换，架构调整 | 高D 高A |
| 🌪️ 混乱调整期 | 大量修复和回滚 | 低U 高A |
| 💤 沉寂停滞期 | 代码变更量极低 | 低D 低A |
| ✨ 谐振态 | 增长健康，协作高效 | 高U 高D 低A |

## 快速开始

```bash
# 安装依赖并编译
npm install
npm run build

# 在当前目录的 Git 仓库中运行
node dist/cli/main.js .

# 或指定仓库路径
node dist/cli/main.js /path/to/repo
```

## 命令行选项

```bash
node dist/cli/main.js [path] [options]

参数:
  path                仓库路径（默认: .）

选项:
  -n, --max-commits   最大分析commit数（默认: 500）
  -s, --since         起始日期（如 "2024-01-01"）
  -u, --until         结束日期
  -b, --branch        指定分支
  --json              以JSON格式输出
  --chapters-only     仅显示章节列表
```

## 项目结构

```
├── package.json          # 项目配置
├── tsconfig.json         # TypeScript 编译配置
├── bin/cli.js            # CLI 入口脚本
└── src/
    ├── cli/main.ts       # CLI 命令行入口
    └── core/
        ├── types.ts      # 核心类型定义
        ├── config.ts     # 全局配置（可协商权重）
        ├── git-parser.ts # Git 历史解析器
        ├── harmony-engine.ts    # 和谐度引擎
        └── narrative-generator.ts # 叙事生成器（SNI核心）
```
